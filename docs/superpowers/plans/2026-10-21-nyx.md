# Nyx Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Nyx, a single-exe Windows torrent client with forced peer encryption, SOCKS5 proxy, queue, scheduler and a dark custom UI.

**Architecture:** A Cargo workspace. `nyx-engine` wraps libtorrent-rasterbar through a thin `cxx` C++ shim and exposes a safe Rust API. `nyx-core` holds pure logic (validation, queue, scheduler, settings) with no libtorrent dependency, so it tests fast. The Tauri 2 app in `src-tauri` glues them together and serves a Svelte UI that contains no torrent logic.

**Tech Stack:** Rust (stable, MSVC), Tauri 2, libtorrent-rasterbar 2.0.x via vcpkg (`x64-windows-static`), `cxx`, Svelte + TypeScript + Vite, Vitest, Playwright, `proptest`.

**Spec:** `docs/superpowers/specs/2026-10-21-nyx-design.md`

## Global Constraints

- Output is one portable `nyx.exe`, under 30 MB, statically linked (`+crt-static`), UI embedded, no installer.
- Windows 11 only. WebView2 is assumed present; show a clear message if it is missing.
- Encryption default: `pe_forced`, RC4 only. A setting offers "prefer encrypted".
- SOCKS5 proxy covers peers, trackers and DHT. If the proxy is set but unreachable, never connect directly.
- With a proxy active: local peer discovery, UPnP and NAT-PMP are off.
- Strict CSP, no remote content or scripts in the webview, minimal Tauri capabilities. No telemetry; no network traffic except torrent traffic.
- `.torrent` and magnet input is untrusted: size and depth limits, and save paths cannot escape the target folder.
- Data lives in `%APPDATA%\Nyx`; if `nyx.portable` sits beside the exe, data lives beside the exe instead.
- Dark theme only: near-black base, violet and cyan accents, glass panels, custom title bar.
- Every file gets a header comment and every function a what/why comment. The owner edits by hand.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Tests that open windows run off-screen and muted, and never kill processes by name, only by the PID they spawned.

## Review Focus

Each line below has its test in the named task.

1. Magnet with uppercase hex, base32 or v2 (`btmh`) hash, missing `xt`, or junk parameters: parse or reject cleanly, never panic. (Task 2)
2. Torrent file paths containing `..`, absolute paths, drive letters, Windows reserved names (`CON`, `NUL`), trailing dots or spaces, or exceeding 260 characters: rejected, never written outside the save folder. (Task 2)
3. Adding the same torrent twice (magnet then file, or twice): one torrent, no error, trackers merged. (Task 3)
4. Save folder missing, unwritable or disk full: that torrent shows an error message, the app stays up. (Task 6)
5. Magnet clicked while Nyx is starting or sitting in the tray: the running instance receives it, no second window. (Task 13)
